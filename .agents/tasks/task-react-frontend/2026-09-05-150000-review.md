# Rebuild the Quiz App frontend as a React 18 + Vite 5 + TypeScript SPA

The vanilla dependency-free SPA (`app.js`/`admin.js`/`config.js` + a top-level `styles.css`) is replaced with a hand-authored Vite multi-page React app under `frontend/`: `index.html` → `src/main.tsx` → `HomePage`, and `admin.html` → `src/admin-main.tsx` → `AdminPage`, sharing a typed API client (`src/api.ts`), Cognito implicit-grant helpers (`src/auth.ts`), and runtime config (`src/config.ts`). The public flow gains a card list, a progress indicator, and a result screen with a score ring and per-question correct-answer reveal; the admin flow keeps the exact Cognito Hosted UI dance and the byte-identical quiz-builder validation. No backend/CDK/Lambda file is touched, and the admin page is deliberately served at the real static path `/admin.html` so the Cognito `redirect_uri` matches the CDK-registered callback/logout URLs without a CDK change.

Watch for: the frontend `npm run build` will fail before Vite ever runs — `frontend/tsconfig.node.json` sets both `composite: true` and `noEmit: true`, which `tsc -b` rejects for a referenced project (**confirmed**). Everything else — API contract parity, the answerIndex-over-non-empty-options semantics, the Cognito flow, and the /admin.html routing decision — checks out. Because the build is broken, this cannot ship as-is.

**Verdict**: NEEDS_CHANGES

## High-level view

The build is the one blocking problem. The `build` script is `tsc -b && vite build`; `tsc -b` walks the project references and errors on `tsconfig.node.json` because a composite (referenced) project may not disable emit. This was reproduced locally with `tsc -b` and it exits non-zero before Vite runs, so Amplify's build phase fails and nothing is published. The fix is one line: drop `noEmit` from `tsconfig.node.json` (keep `composite: true`), which is exactly the shape the official Vite react-ts template ships.

Behavioral parity with the old vanilla frontend is faithful. The API client calls the same relative paths on top of `API_BASE` with the same content-type guard and the same Japanese error strings; submit builds `answers: number[]` indexed by question `n` with `-1` for unanswered; the admin `collectPayload` reproduces every validation branch, error message, and the skip-blank `answerIndex` computation from the old `admin.js` exactly. The Cognito helpers mirror the old login/logout URLs, the 60s margin / 3600s default, the `quizAdminToken` sessionStorage key, and the `history.replaceState` hash strip.

The /admin.html routing decision is sound: the CDK registers callback/logout URLs as `${adminAppBaseUrl}/admin.html` (plus a gated `http://localhost:8080/admin.html`), and the React admin app is a real static entry at `/admin.html` whose `adminPageUrl()` returns `origin + pathname`, so the `redirect_uri` matches with no CDK change and no SPA rewrite rule. The `amplify.yml` VITE_* mapping, the cross-phase `cd frontend`, and the `npm ci || npm install` fallback are all handled correctly.

The UI is genuinely richer while staying lean (deps are `react` + `react-dom` only; `react-router-dom` was removed): a card-based quiz list, an answered-progress bar, a conic-gradient score ring with percentage, per-question green/red feedback that reveals the correct option text on wrong answers, and `prefers-color-scheme` dark mode. The gap is verification: no build, type-check, or runtime smoke test could run in this sandbox, so correctness rests on reading plus the one reproduced build error.

### `tsc -b` fails on the composite `noEmit` config

`frontend/package.json` builds with `"build": "tsc -b && vite build"`. `tsc -b` treats `tsconfig.json` as the build root and walks its `references`, which point at `tsconfig.node.json`. That node config sets:

```jsonc
// frontend/tsconfig.node.json
{ "compilerOptions": { "composite": true, ..., "noEmit": true } }
```

A project referenced under `-b` must be composite so its outputs can be consumed, and a composite project may not disable emit. Reproduced locally:

```
$ tsc -b .
tsconfig.json(4,15): error TS6310: Referenced project '.../tsconfig.node.json' may not disable emit.
```

Under the pinned `typescript@~5.5.4` the wording is TS6379 ("Composite projects may not disable emit") rather than TS6310, but it is the same failure class and the same non-zero exit. Because `&&` short-circuits, `vite build` never runs and `frontend/dist` is never produced, so the Amplify `build` phase (`cd frontend && npm run build`) fails and no artifact is published. The task's own verification block already flagged this as an open risk; it is confirmed real and blocking.

Fix: remove `noEmit` from `tsconfig.node.json` and keep `composite: true` (verified locally that `tsc -b` then exits 0). This matches the canonical Vite `react-ts` template, whose node tsconfig is composite and does not set `noEmit`. The app `tsconfig.json` keeps `noEmit: true` (correct — it is not composite, and `allowImportingTsExtensions` requires it).

### API contract parity with lambda/index.ts

Verified against `lambda/index.ts` and the old `app.js`: `src/api.ts` calls the same relative paths on top of `API_BASE` (`/quizzes`, `/quizzes/{id}`, `/quizzes/{id}/submit`, `/admin/quizzes`), and `config.ts` keeps the `/api` default plus trailing-slash strip, so the effective URLs still resolve to the Lambda's `/api/...` routes. The one correctness-critical detail: `submitAnswers` posts `answers = quiz.questions.map((q) => q.n in selected ? selected[q.n] : -1)`, a `number[]` with `-1` for unanswered, and the Lambda scores by `answers[q.n] === q.answerIndex` — so indexing the array by question position (dense, 0-based `n`) is preserved rather than by array order. The content-type guard, the "unexpected non-JSON" string, and `createQuiz`'s 401 → `AuthError` / 403 → `権限がありません` / other-non-ok → body `message` mapping are carried over verbatim.

### Admin validation and answerIndex-over-non-empty-options

`AdminPage.collectPayload` reproduces the old `admin.js` branch order and Japanese strings exactly (title required, ≥1 question, per-question text, ≥2 non-empty options, correct radio selected, `/^[a-z0-9-]+$/` quizId). The subtle part is faithful: it finds the checked row's index across *all* option rows, then re-counts only non-empty rows to translate that into an index over the trimmed `options` array, emitting `問題 N の正解は空でない選択肢を選んでください。` when the checked row is blank — so a correct answer sitting after a skipped blank still yields the right `answerIndex`. For equivalent input the payload is byte-identical to the old builder.

### Cognito Hosted UI implicit-grant flow

`src/auth.ts` matches `admin.js` on the security-relevant details: `STORAGE_KEY = 'quizAdminToken'`, login/logout URLs with `response_type=token&scope=openid+email+profile`, the `expiresAt = Date.now() + (seconds - 60) * 1000` margin with the 3600s default on missing/invalid `expires_in`, and the `history.replaceState` fragment strip that keeps the token out of the visible URL. On submit `AdminPage` re-checks `isAuthenticated` before calling `createQuiz`, a 401 `AuthError` clears the token and returns to login, and a 403 surfaces `権限がありません`.

One divergence from the old code: `redirectToLogin` used to short-circuit with a config-missing message when `COGNITO_DOMAIN`/`COGNITO_CLIENT_ID` were empty; the React `handleLogin` navigates to `loginUrl()` unconditionally, so empty config sends the user to a malformed URL instead of an inline warning. Not a happy-path regression (Amplify injects the values), but it drops a diagnostic the old page had.

### /admin.html routing preserves the Cognito contract without a CDK change

`lib/quiz-app-stack.ts` builds `callbackUrls`/`logoutUrls` as `${adminAppBaseUrl.valueAsString}/admin.html` (with `http://localhost:8080/admin.html` pushed only behind the synth-time gate). The multi-page Vite build emits a real `/admin.html`, and `auth.ts` computes the `redirect_uri`/`logout_uri` from `origin + pathname`, which on that page is exactly `<origin>/admin.html`. Cognito requires an exact match, and this matches — so serving the admin app as a static file instead of a client-side `/admin` route removes the need for both an Amplify SPA rewrite and any CDK edit. `react-router-dom` is gone from `package.json` with no remaining router imports.

### Amplify build wiring

`amplify.yml` writes `frontend/.env` from the Amplify console vars via heredoc, keeping the same console variable names. `cd frontend` in `preBuild` persists across that phase's commands, and the `build` phase re-issues `cd frontend` because the working directory resets between phases — both handled. `npm ci || npm install` falls back cleanly given no committed lockfile. One low-severity risk: `cache.paths: frontend/node_modules/**/*` caches dependencies while no lockfile pins them, so a cached `node_modules` plus `npm install` can drift across builds; committing a lockfile or dropping the cache would make builds reproducible.

### UI richness, dark mode, and the CSSProperties cast

The `.gitignore` `*.d.ts` rule would have swallowed `src/vite-env.d.ts`; the author added a `!frontend/src/vite-env.d.ts` negation and it is tracked (`git ls-files` confirms, `git check-ignore` returns nothing). The result screen drives a `conic-gradient` score ring from a `--percent` CSS custom property set inline via `{ '--percent': percent } as CSSProperties`; the `as` cast is required because custom properties aren't in the `CSSProperties` type, and it type-checks (all `CSSProperties` fields are optional, so the assertion is valid). Dark mode comes from a `@media (prefers-color-scheme: dark)` block overriding the CSS variables. With the card list, the answered-progress bar, and the per-question correct-answer reveal (bounds-checked against the loaded quiz options via `result.results[].answerIndex`), the UI is materially richer than the old plain lists while keeping runtime deps to `react` + `react-dom`.

### Test coverage

Not tested: there are no frontend tests, and the blocked npm registry meant `tsc -b`, `vite build`, and any runtime smoke test could not run — parity rests on code reading plus the one reproduced `tsc -b` error. After removing `noEmit` from the node tsconfig, a networked `cd frontend && npm install && npm run build` must confirm both `dist/index.html` and `dist/admin.html` emit, followed by a manual smoke test of both flows against a deployed API. The backend CDK/Lambda tests are unaffected (those files are untouched in this diff).
