## High-level view

All four v1 issues are resolved coherently. The frontend/API origin gap — the v1 blocker — is closed at the infrastructure layer rather than papered over with a manual step: a CloudFront `api/*` behavior forwards to the HTTP API, the routes were re-prefixed to `/api`, and the SPA default of `/api` now hits a real same-origin path. The prefix is consistent across the stack routes, the Lambda `routeKey` guards, the SPA calls, and the stack test.

The API-error-as-HTML concern is handled given the CloudFront constraint. Custom error responses can't be scoped per-behavior, so `fetchJson` now inspects `content-type` and raises a clear error when a swallowed 4xx comes back as `index.html`/200.

The dependency floor and seeding robustness are straightforward fixes: `aws-cdk-lib`/`aws-cdk` moved to `^2.156.0` matching the OAC helper actually used, and BatchWrite now retries `UnprocessedItems` with bounded linear backoff. The open CORS stays `['*']` but is now a reasoned decision — same-origin routing means browsers don't preflight, tightening to the CloudFront domain would introduce a circular stack dependency, and the demo persists no per-user data. Tests grew a handler-level assertion that `answerIndex` never appears in the public payload (via the new exported `toPublicQuestions`) and a distribution assertion for the `api/*` behavior.

### Frontend-to-API gap closed via same-origin CloudFront routing

```
Browser ──► CloudFront distribution
                ├── default behavior            ──► S3 (private, OAC)   [SPA assets]
                └── behavior PathPattern 'api/*' ──► HttpOrigin(apiDomain) [HTTP API]
                        ALLOW_ALL, CACHING_DISABLED,
                        ALL_VIEWER_EXCEPT_HOST_HEADER

fetch('/api/quizzes')  →  CloudFront 'api/*'  →  execute-api host  →  route 'GET /api/quizzes'
```

The prefix is consistent at every hop, which is the thing most likely to break in a change like this: the stack registers `/api/quizzes`, `/api/quizzes/{quizId}`, `/api/quizzes/{quizId}/submit`; the Lambda matches `routeKey` on the same three `/api/...` strings; `app.js` prepends `/api` and calls `/quizzes`, `/quizzes/{id}`, `/quizzes/{id}/submit`; and the stack test asserts those exact route keys plus a `PathPattern: 'api/*'` cache behavior. CloudFront forwards the matched path unmodified to the origin, so `/api/quizzes` arrives at the API as `/api/quizzes` — no edge rewrite needed, and no stage prefix problem because the HTTP API default stage serves at the root of `apiEndpoint`.

`ALL_VIEWER_EXCEPT_HOST_HEADER` is required here: the `HttpOrigin` must present its own `execute-api` host, not the CloudFront domain, so forwarding the viewer Host header would break origin routing.

The origin host is extracted with `cdk.Fn.select(2, cdk.Fn.split('/', httpApi.apiEndpoint))`. For `https://<id>.execute-api.<region>.amazonaws.com` this splits to `['https:', '', '<host>']` and selects the host at index 2. This is resolved at deploy time from a CloudFormation token, so it can't be verified by reading alone; the arithmetic is right for the standard endpoint shape, but a `cdk synth` on a networked checkout is the confirmation.

### API errors no longer masquerade as HTML behind a JSON parse

CloudFront's 403/404→`index.html`/200 mapping is distribution-wide and would rewrite an API 4xx into an HTML 200, which `fetchJson`'s `res.ok`-only check missed in v1. The fix guards on the client: `fetchJson` reads `content-type` and throws a clear, localized error when the body isn't `application/json`, instead of letting `res.json()` crash on HTML. The handler always sets `content-type: application/json`, so legitimate API errors (400/404/500) still return JSON; only a CloudFront-swallowed response trips the guard.

### Seeding retries UnprocessedItems

`seedSampleData` now loops up to 5 attempts per chunk, feeding `UnprocessedItems` back into the next `BatchWriteCommand` with linear backoff (`50 * (attempt+1)` ms), closing the v1 gap where a throttled batch could leave the table half-populated. Writes remain idempotent by key, so concurrent cold-start seeds still converge.

### CORS kept open as a documented trade-off

`allowOrigins: ['*']` stays, now with a comment explaining the reasoning: the SPA calls same-origin through the `api/*` behavior so browsers don't issue cross-origin preflights in normal use; tightening to the CloudFront domain would reference a domain created in the same stack and introduce a circular dependency; and the demo is public, unauthenticated, and persists no per-user data. The submit path remains unauthenticated and unmetered, bounded by the fact that it neither reads nor writes user identity.

### Tests: answer-stripping now asserted at the projection boundary

The answer-stripping projection was refactored into an exported pure `toPublicQuestions`, and `handler.test.ts` gained a suite asserting the projected payload never carries `answerIndex` — both via property check and a `JSON.stringify(...).not.toContain('answerIndex')` deep scan. The handler calls this exact function on the `GET /api/quizzes/{quizId}` path, so a regression that stopped stripping the answer would fail the test. `quiz-app-stack.test.ts` updated the three route keys to the `/api` prefix and added a `PathPattern: 'api/*'` cache-behavior assertion, guarding the same-origin wiring.

Not tested: the handler's routing and DynamoDB-backed paths (400/404/500 branches, the empty-table seeding branch, the BatchWrite retry loop) are exercised only indirectly through the pure helpers; the `Fn.split` origin extraction is asserted only as a `PathPattern` presence, not that the origin domain resolves to the API host. The frontend has no tests. None of the suites have run here (no network for `npm ci`/`jest`/`cdk synth`), so passing status is asserted by construction.
