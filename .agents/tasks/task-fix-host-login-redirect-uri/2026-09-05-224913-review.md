# Canonicalize host OAuth redirect to ROOT to fix redirect_mismatch (v1)

The realtime-battle host reuses the admin Cognito Hosted UI, but its view lives in the public app that Amplify serves at the site ROOT. After Hosted UI login the browser lands on `origin + '/'`, while the Cognito app client only trusted `origin + '/admin.html'` and `origin + '/index.html'`. Since Cognito requires an exact `redirect_uri` match and the browser never actually lands on `/index.html`, host login failed with `redirect_mismatch` while the admin page (served at `/admin.html`) kept working. The fix makes the host's `redirect_uri` the canonical ROOT `origin + '/'`, registers that exact string in the CDK app client (dropping the never-matched `/index.html`), and threads an explicit `redirectUri` argument through `loginUrl`/`logoutUrl` so each page sends its own registered value. Admin keeps `/admin.html`; the host uses `/`.

Watch for: the fix only takes effect after BOTH a backend redeploy with an explicit `adminAppBaseUrl` AND a frontend rebuild/redeploy (confirmed, documented in README). A `adminAppBaseUrl` value with a trailing slash would silently reintroduce `redirect_mismatch` via a doubled slash in the ROOT entry (possible). The host's token is still only captured after the user clicks into the host view, not on landing at ROOT (confirmed, but pre-existing and out of scope).

**Verdict**: APPROVED

## High-level view

The redirect contract is now explicit on both sides of the wire. `auth.ts` exposes two canonical helpers, `adminRedirectUri()` (`origin + '/admin.html'`) and `publicRedirectUri()` (`origin + '/'`), and `loginUrl`/`logoutUrl` take the target as an argument instead of deriving it from the current page. The CDK app client registers exactly those two path shapes for both callback and logout URLs. The previously registered `/index.html` is removed because the browser never landed there, so it was dead trust surface rather than a working fallback.

The byte-for-byte pairing holds by inspection: `AdminPage` passes `adminRedirectUri()`, `BattlePage`'s host passes `publicRedirectUri()`, and the CDK strings mirror them. The one place this contract can still break is the `adminAppBaseUrl` parameter itself: it is concatenated raw, so a trailing slash on the supplied value produces `//` in the ROOT entry and breaks the exact match. Nothing normalizes or validates it.

The auth surface change is contained to redirect URIs: the JWT authorizer, issuer/audience/signature verification, WebSocket API, and scoring are untouched, and dropping `/index.html` shrinks the trusted redirect surface rather than expanding it. Test coverage asserts the new localhost callback/logout scheme and the absence of the `/index.html` entries, so a revert of the URL change would fail synth-time tests.

### Explicit redirect_uri threading vs. deriving from the current page

Previously `loginUrl()`/`logoutUrl()` used `adminPageUrl()` (`origin + pathname`), so the redirect target depended on whichever page invoked it. That worked for the admin page (always at `/admin.html`) but was wrong for the host, whose `pathname` at the moment of the login click is not guaranteed to be `/`. The new `loginUrl(redirectUri)`/`logoutUrl(redirectUri)` signatures force each caller to name its registered target, and `adminPageUrl()` is now scoped to fragment cleanup after token capture. Hardcoding `publicRedirectUri()` to `origin + '/'` (rather than reading the current path) makes host login robust even if the host arrived via an `index.html` anchor link elsewhere in the app.

### Byte-for-byte pairing between frontend and CDK

```
frontend/src/auth.ts            lib/quiz-app-stack.ts (AdminAppClient)
------------------------------  --------------------------------------
adminRedirectUri()              ${adminAppBaseUrl}/admin.html
  origin + '/admin.html'  <===> http://localhost:8080/admin.html
publicRedirectUri()             ${adminAppBaseUrl}/
  origin + '/'            <===> http://localhost:8080/
```

The exact-match requirement holds only as long as `adminAppBaseUrl` is passed without a trailing slash. The value is concatenated verbatim, so `https://host/` produces `https://host//` for the ROOT entry and `https://host//admin.html` for admin, neither of which matches the browser origin. The README examples consistently omit the trailing slash, but nothing enforces it. A single `adminAppBaseUrl.valueAsString.replace(/\/$/, '')` (or a documented constraint) would close this.

### Test coverage

The added CDK assertion checks that the localhost callback and logout lists contain `http://localhost:8080/admin.html` and `http://localhost:8080/`, and that neither list contains `http://localhost:8080/index.html`; a revert of the `/index.html` -> `/` change would fail it. It asserts against the localhost entries because the `adminAppBaseUrl`-derived entries are synth-time tokens and not literal-matchable. Not tested: the exact-match behavior against a real (non-localhost) `adminAppBaseUrl`, and the trailing-slash concatenation case that would reintroduce `redirect_mismatch`. The frontend `redirect_uri` construction has no unit coverage, so the byte-for-byte correspondence between the two sides is maintained by inspection only.
